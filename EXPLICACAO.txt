EXPLICAÇÃO DO CÓDIGO - ESCS PORTFOLIO
======================================

Este documento explica como fizemos o projeto e como funciona cada parte.
Escrito para ajudar a explicar ao professor.


1. ESTRUTURA GERAL DO PROJETO
------------------------------

O projeto está dividido em 3 partes principais:

- BASE DE DADOS (MySQL) - onde guardamos toda a informação
- BACKEND (PHP) - onde processamos os pedidos e falamos com a BD
- FRONTEND (HTML/CSS/JS) - o que o utilizador vê e interage


2. BASE DE DADOS (MySQL)
------------------------

Criámos 6 tabelas na base de dados:

A) USERS
   - Guarda os utilizadores admin que podem gerir o site
   - Campos importantes: username, password (encriptada), email
   - A password está guardada com hash para segurança

B) COURSES
   - Lista dos cursos da ESCS (LAM, Jornalismo, etc)
   - Campos: id, name, acronym, description

C) SCIENTIFIC_AREAS
   - Áreas científicas (Programação, Design, Vídeo, etc)
   - Campos: id, name, description

D) CURRICULAR_UNITS
   - Unidades curriculares (disciplinas)
   - Está ligada aos cursos através de course_id (chave estrangeira)

E) PROJECTS
   - A tabela mais importante! Guarda os projetos dos alunos
   - Campos principais:
     * title, description - informação do projeto
     * student_name, student_number - dados do aluno
     * course_id, curricular_unit_id, scientific_area_id - ligações a outras tabelas
     * thumbnail - nome do ficheiro da imagem
     * views - contador de visualizações
     * is_featured - se é projeto em destaque
     * is_published - se está publicado ou não

F) COMMENTS
   - Comentários que os visitantes deixam nos projetos
   - is_approved - só aparecem no site depois de aprovados


PORQUÊ ESTAS TABELAS?
Separámos a informação em várias tabelas para não repetir dados.
Por exemplo: em vez de escrever "Licenciatura em Audiovisual..." em cada projeto,
guardamos só o ID do curso e depois fazemos JOIN para buscar o nome completo.
Isto chama-se normalização da base de dados (aprendemos nas aulas).


3. BACKEND - APIs EM PHP
-------------------------

Criámos vários ficheiros PHP que funcionam como APIs (Application Programming Interface).
APIs são como "portas de entrada" para aceder aos dados.

A) backend/config/db.php
   - Faz a ligação à base de dados
   - Usa PDO (PHP Data Objects) que é mais seguro que mysql_connect antigo
   - Define o host, nome da BD, username e password

   Como funciona:
   ```
   new PDO("mysql:host=localhost;dbname=escs_portfolio", "root", "")
   ```
   Isto cria uma conexão que depois usamos nos outros ficheiros.

B) backend/api/get_projects.php
   - Lista todos os projetos
   - Aceita filtros via GET (ex: ?course_id=1)

   Como funciona:
   1. Recebe os parâmetros do URL ($_GET)
   2. Constrói uma query SQL com base nos filtros
   3. Faz JOIN com as outras tabelas para buscar nomes dos cursos, etc
   4. Executa a query
   5. Retorna os resultados em JSON

   Exemplo de SQL que construímos:
   ```sql
   SELECT p.*, c.name as curso_nome
   FROM projects p
   LEFT JOIN courses c ON p.course_id = c.id
   WHERE p.is_published = 1
   ```

   O LEFT JOIN serve para trazer dados de 2 tabelas ao mesmo tempo.

C) backend/api/get_project.php
   - Busca UM projeto específico pelo ID
   - Também incrementa o contador de views

D) backend/api/add_project.php
   - Adiciona um projeto novo
   - Só funciona se o utilizador estiver logado (verifica a sessão)
   - Faz upload da imagem thumbnail se existir

   Como funciona o upload:
   1. Recebe o ficheiro em $_FILES['thumbnail']
   2. Gera um nome único: uniqid() + extensão
   3. Move o ficheiro para a pasta uploads/thumbnails/
   4. Guarda o nome na base de dados

E) backend/api/delete_project.php
   - Apaga um projeto
   - Também apaga a imagem do servidor

F) backend/api/login.php
   - Faz o login dos administradores
   - Verifica username e password
   - Usa password_verify() para comparar com o hash guardado na BD
   - Se correto, cria uma sessão PHP

   Como funciona a sessão:
   ```php
   session_start();
   $_SESSION['user_id'] = $usuario['id'];
   $_SESSION['logado'] = true;
   ```
   A sessão fica guardada no servidor e permite saber se o user está logado.

G) backend/api/add_comment.php
   - Adiciona comentários aos projetos
   - Os comentários ficam com is_approved = 0 (precisam aprovação)


PORQUÊ JSON?
Todos os ficheiros PHP retornam JSON (JavaScript Object Notation).
É um formato leve e fácil de ler em JavaScript.
Exemplo:
```json
{
  "success": true,
  "data": {
    "projects": [...]
  }
}
```


4. FRONTEND - HTML, CSS, JAVASCRIPT
------------------------------------

A) frontend/index.html
   - A página principal que o utilizador vê
   - Tem a estrutura HTML básica
   - Carrega o CSS (estilos) e o JavaScript (funcionalidade)

   Elementos principais:
   - Header com o título
   - Filtros (dropdowns e input de pesquisa)
   - Grid onde aparecem os cards dos projetos
   - Modal (popup) para ver detalhes do projeto

B) frontend/css/style.css
   - Define o visual do site
   - Usa CSS Grid para organizar os cards dos projetos:
     ```css
     .projects-grid {
       display: grid;
       grid-template-columns: repeat(auto-fill, minmax(300px, 1fr));
     }
     ```
   Isto cria uma grelha responsiva que se adapta ao tamanho do ecrã.

   - Media queries para mobile:
     ```css
     @media (max-width: 768px) {
       .projects-grid { grid-template-columns: 1fr; }
     }
     ```

C) frontend/js/app.js
   - Aqui está a lógica toda do site em JavaScript

   COMO FUNCIONA:

   1. Quando a página carrega:
      ```javascript
      window.onload = function() {
        carregarCursos();
        carregarAreas();
        carregarUnidades();
        carregarProjetos();
      }
      ```
      Carrega todos os dados necessários.

   2. Para carregar dados, usamos FETCH (chamadas AJAX):
      ```javascript
      fetch('../backend/api/get_projects.php')
        .then(response => response.json())
        .then(data => {
          // fazer algo com os dados
        })
      ```

      O FETCH é assíncrono - não bloqueia a página enquanto espera.
      O .then() executa quando a resposta chega.

   3. Para mostrar os projetos:
      - Criamos elementos HTML dinamicamente com document.createElement()
      - Preenchemos com os dados do projeto
      - Adicionamos ao DOM (Document Object Model)

   4. Os filtros:
      - Quando o utilizador escolhe filtros e clica "Aplicar"
      - Pegamos os valores dos inputs
      - Construímos um URL com query strings
      - Fazemos novo FETCH com esse URL
      - Os dados filtrados vêm do backend

   5. O Modal (popup):
      - Quando clicamos num projeto, chamamos abrirModal(id)
      - Fazemos FETCH para get_project.php?id=X
      - Mostramos os detalhes numa div que aparece por cima
      - Para fechar, mudamos display: none


5. PAINEL DE ADMINISTRAÇÃO
---------------------------

A) backend/admin/login.php
   - Página de login simples
   - Form que submete para a API de login
   - Se sucesso, redireciona para projetos.php

B) backend/admin/projetos.php
   - Interface para gerir projetos
   - Tem um formulário para adicionar projetos
   - Lista todos os projetos existentes
   - Botão para apagar cada projeto

   Como funciona adicionar projeto:
   1. Utilizador preenche o form
   2. JavaScript captura o submit
   3. Cria um FormData com os dados do form
   4. Faz FETCH POST para add_project.php
   5. Se sucesso, recarrega a lista

C) backend/admin/estilo.css
   - Estilos simples para o admin
   - Layout com sidebar (menu lateral)


6. CONCEITOS IMPORTANTES QUE USÁMOS
------------------------------------

A) SESSÕES PHP
   - Permitem guardar informação entre páginas
   - Usamos para saber se o admin está logado
   - Funciona com cookies no navegador

B) PREPARED STATEMENTS (em alguns sítios)
   - Protege contra SQL Injection
   - Exemplo:
     ```php
     $stmt = $conn->prepare("SELECT * FROM users WHERE id = :id");
     $stmt->bindParam(':id', $id);
     ```

C) AJAX / FETCH
   - Permite comunicar com o servidor sem recarregar a página
   - Faz o site mais rápido e dinâmico

D) JSON
   - Formato para trocar dados entre PHP e JavaScript
   - PHP: json_encode() converte array para JSON
   - JS: response.json() converte JSON para objeto

E) VALIDAÇÃO
   - HTML: required nos inputs
   - PHP: verificar se campos estão vazios
   - JS: verificar antes de submeter

F) ENCRIPTAÇÃO DE PASSWORDS
   - password_hash() para encriptar
   - password_verify() para verificar
   - Nunca guardamos passwords em texto simples!


7. FLUXO DE FUNCIONAMENTO
--------------------------

EXEMPLO: Ver lista de projetos

1. Utilizador abre index.html
2. JavaScript executa window.onload
3. Chama carregarProjetos()
4. Faz FETCH para get_projects.php
5. PHP liga à BD e faz SELECT
6. PHP retorna JSON com os projetos
7. JavaScript recebe os dados
8. JavaScript cria os cards HTML
9. JavaScript adiciona ao DOM
10. Utilizador vê os projetos no ecrã


EXEMPLO: Adicionar projeto (admin)

1. Admin faz login
2. Preenche formulário
3. Clica "Guardar"
4. JavaScript captura o submit
5. Cria FormData com os dados
6. Faz FETCH POST para add_project.php
7. PHP verifica se está logado (sessão)
8. PHP faz upload da imagem
9. PHP insere na BD com INSERT
10. PHP retorna sucesso em JSON
11. JavaScript mostra alert("Projeto adicionado!")
12. Recarrega a lista de projetos


8. DIFICULDADES QUE TIVEMOS
----------------------------

- No início tínhamos problemas com CORS (Cross-Origin)
  Solução: Adicionar headers no PHP

- Upload de ficheiros deu erro
  Solução: Criar as pastas uploads/ e dar permissões

- Às vezes os dados não apareciam
  Solução: Verificar console.log() para ver os erros

- SQL dava erro
  Solução: Testar as queries direto no phpMyAdmin primeiro

- JSON não parseava
  Solução: Verificar se o PHP não tinha echo antes do JSON


9. MELHORIAS QUE PODÍAMOS FAZER
--------------------------------

- Usar prepared statements em TODAS as queries (mais seguro)
- Adicionar paginação real (agora vem tudo de uma vez)
- Sistema de editar projetos (só temos criar e apagar)
- Aprovar comentários no admin
- Validação mais forte dos inputs
- Mensagens de erro mais bonitas (em vez de alert())
- Loading spinner enquanto carrega
- Otimizar imagens antes de fazer upload


10. CONCLUSÃO
-------------

Este projeto usa conceitos básicos de desenvolvimento web:
- Base de dados relacional (MySQL)
- Backend com PHP para processar pedidos
- Frontend com JavaScript para interatividade
- APIs REST para comunicação
- Sessões para autenticação
- AJAX para não recarregar a página

É um sistema CRUD básico (Create, Read, Update, Delete) aplicado
a um portfolio de projetos de estudantes.

O código não é perfeito mas funciona e cumpre os requisitos do trabalho.
Aprendemos muito a fazer isto!
